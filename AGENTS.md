# Project Rules
- New TTO tickets require a tenant-validated contracted assignment; immutable private tto_ticket_terms snapshots supply export/payroll rates, currency and the sole contract supervisor, while public creation RPCs delegate to private role-checked functions; why: agreed pay and legal reviewer must not drift or leak to workers.
- Agency time-ticket decisions use the service-only decide_contracted_time_ticket RPC to lock the submitted ticket and save the decision, status and audit together; why: duplicate approvals and partially recorded decisions cannot produce payable work.
- Payroll and billing CSVs use the shared contract-export builder and frozen ticket terms, never mutable Rate Book entries; why: the tested export must preserve the exact agreement and reject missing or mixed-currency terms.
- Payroll Prep, saved reviews and CSV exports share payroll-calculation and payroll-data: full Monday–Sunday context preserves weekly overtime across pay-period boundaries, manual deductions reduce gross pay once, and service-only review/export locks freeze the reviewed snapshot; why: visible net pay must match exported pay without invented withholding or duplicate payment.
- Contract calendar terms use date-fns and entered actual shifts use date-fns-tz to convert the selected zone to UTC timestamps; why: a contract's duration is not paid hours and daylight saving must not shift recorded work.

- Compliance reports audit screening metadata before displaying it, scope agency reads explicitly, and leave platform security findings super-admin-only; why: consolidated review must preserve existing privacy and access traceability.
- Screening detail screens share worker and read-only agency views; agency reads use explicit safe fields and audited tenant-scoped access, while signing remains on the worker-only versioned RPC; why: reviewers must never sign on a worker's behalf.

- Database privacy (RLS) regression tests live in `supabase/tests/*.sql`; each runs inside a transaction and rolls back, so it can be run safely against the live database.
- Screening record reads/downloads/signs go through log_screening_access / get_screening_document / sign_screening_consent so every access lands in the immutable screening_access_log; why: compliance traceability (SELECT can't be audited by triggers).
- Module events for Automation Studio are published by the private.publish_module_event DB trigger (insert / status change / delete → '<type>.<status>' in ttos_events, PII keys stripped, instant ttos-dispatch call + hourly backstop); why: catches every write path, not just UI calls.
- Sensitive automation actions (launch_drug_test, generate_payroll, escalate_issue) are never run by ttos-dispatch; it queues automation_action_approvals and they execute only via decide_automation_action, which checks private.automation_action_roles and writes the immutable automation_approval_audit; why: human sign-off with role checks for high-impact steps.
- Automation condition/action-planning logic lives in src/lib/automation/simulate.ts and is copied verbatim to supabase/functions/_shared/automation-sim.ts for ttos-dispatch; why: Studio simulations must match live engine behaviour — edit both together.
- ttos-dispatch claims each event atomically (status=processing) and reserves every action in ttos_action_ledger keyed by correlation root; unique (correlation_id, fingerprint) and (correlation_id, conflict_key) make duplicates/contradictions race-safe, first by priority wins, chains stop at MAX_CHAIN_DEPTH; static analysis in src/lib/automation/conflicts.ts mirrors these rules; why: at-most-once, non-contradictory automation effects.
- Client ticket sign/reject is advised by the woic-ticket-review edge function (RLS-scoped ticket read, deterministic checks in checks.ts, WOIC reason+recommend, guardrail: failed check never yields 'sign'); results in ticket_ai_reviews and a tickets trigger records final_decision/followed. WOIC never signs or rejects; why: human signature remains the legal decision, with full explainability.
- WOIC endpoint access is decided by supabase/functions/_shared/woic-policy.ts (tenant membership + role matrix per resource/read-write + calling-module scope) via requireWoicAccess, which logs every decision to woic_access_audit; the file is mirrored verbatim in src/lib/woic/policy.ts (test enforces equality); why: one auditable RBAC source for memory, knowledge and compliance data.
- Event replay runs only through the event-replay edge function: admin role check, dry-run preview returns a plan hash (events + rule versions) that execution must match, explicit confirm when the plan creates records, originals copied as new events (metadata.replay_of, fresh correlation id) and every request logged to event_replay_runs; planning logic in supabase/functions/_shared/replay-plan.ts is mirrored in src/lib/activity/replay-plan.ts; why: replays are previewable, auditable and never rewrite history.
- Live Observations reads the Event Fabric (ttos_events) directly via src/hooks/perception/use-observation-stream.ts (server-side search/freshness/source filters, realtime + pause buffer) and stores per-user pins in perception_observation_pins (RLS: own pins, own agency); why: no deployed woic-perception API, so the real stream is the fabric.
- Context Packs are derived client-side from woic_cognitive_requests + linked woic_reasoning_traces (output.trace_id) by src/lib/perception/context-pack.ts (coverage facets, worst-evidence freshness, gaps, supports-vs-contradicts per reference); why: no deployed woic-perception API, so packs come from real WOIC storage.
- Perception privacy display (classification, sensitive markers, tenant scope, evidence provenance) uses src/lib/perception/privacy.ts tiers (none/staff/admin/super); restricted keys are never rendered and markers expose paths only; why: one consistent display-layer privacy rule on top of RLS.
- Passport share-link owner notices are written by the private.notify_share_owner trigger on passport_sharing (opened/revoked) and an hourly private.notify_expired_share_links sweep into passport_share_notifications (realtime); ShareLinkNotifier also toasts at exact expiry client-side; why: covers every write path without sub-hourly polling.
- Reasoning workspace calls woic-reasoning for tenant-scoped reads and explicit reviews; two independent model positions and their comparison are stored in woic_reasoning_reviews without overwriting source traces, with reviewed evidence references validated and human actions in an append-only ledger; why: real disagreements must remain traceable and never be manufactured or averaged away.
- Keep vector in the extensions schema and include extensions in the pinned woic_match_memory search path; why: prevents public add-on exposure while retaining vector operator resolution.
- Worker screening pages use read_worker_screening, sign_screening_consent_version and download_worker_screening RPCs with private ownership guards and locked version checks; why: every displayed/read/signed/downloaded document is audited at its actual version and stale consent cannot be signed.
- Client invoices (pb-generate-invoices) bill only frozen tto_ticket_terms bill rates via _shared/contract-invoice.ts, one draft per client and currency, skipping already-invoiced tickets; markup is entered as a percentage that sets the contract bill rate; why: invoices must match the agreed contract and never double-bill.
